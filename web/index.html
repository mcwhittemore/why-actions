Stacked-PR cascades

A burst is one person's push touching CI on several PRs within 2 minutes. When the PRs are linked by base branch (or 3+ PRs move at once), every PR other than the lowest in the stack counts as cascade.

How this is computed
  • Billed minutes: each job's duration rounded up to a whole minute, ×2 for Windows and ×10 for macOS runners, self-hosted counted as 0. This approximates GitHub billing; public repos are not billed at all.
  • Re-run attempt: jobs from attempt 2+ of a run, counted separately from the run's original cause.
  • Same commit again: the same workflow already ran on the same SHA earlier (for example a push and a pull_request event for one commit).
  • Stacked-PR cascade: see the cascade section. Stacks come from PR base branches, including earlier bases that were later retargeted.
  • PR: first run / new commits: the first run of a workflow for a PR, and every later one.
  • Runs are matched to PRs from the run's PR list, or by head branch while the PR was open.
